### D&D Interaction Mode

For fresh intentions in D&D mode, choose one `interaction_mode` before setting
Cat I or Cat II fields.

- `cat_i`: ordinary self-closing narrative action.
- `cat_ii`: non-combat contested interaction. Use this for consent-dependent
  contact, grabbing an object, blocking passage, or other contests that are not
  a hostile fight.
- `dnd_combat_start`: a hostile attack, attack spell, weapon threat becoming
  violence, or similar fight-starting action. Do not open Cat II for this mode.
- `dnd_combat_end`: active hostilities clearly end through surrender, flight,
  defeat, or mutual de-escalation.

For `dnd_combat_start`, set `requires_responders=false`,
`required_responders=[]`, and put the acting character, direct targets, and
other immediately involved combatants in `combatant_ids`. Observable facts show
the combat-starting trigger only; do not resolve attack rolls, hits, damage, or
spell effects before initiative.

If a fight starts against a hostile creature that is not already in the roster,
add it to `combatant_spawns`, include the new `character_id` in `combatant_ids`,
and fill the compact stat block from your best D&D 5e rules knowledge. Use this
only for combat-ready creatures such as rats, wolves, goblins, bandits, guards,
summoned creatures, or other standard hostile participants. Do not use it for
named story NPCs, player characters, allies whose identity should persist as a
full character, or ordinary bystanders.

For spawned combatants, use a stable snake_case `monster_key` for the standard
creature name when one is implied, such as `rat`. The stat block must include
armor class, hit points, ability scores, senses, actions, challenge rating, and
XP. Keep the values conservative when uncertain. Use empty lists/strings for
parts that do not apply.

Also seed `battle_map_seed` for `dnd_combat_start` when the fiction gives enough
spatial context to establish a tactical grid. Use a simple square battle map:
dimensions in squares, 5 feet per square, no larger than 80x80, one token per
combatant, and terrain zones only for visible blockers, cover, hazards, or
difficult ground. For tokens, use token_id for the exact combatant token and
character_id for the underlying character. Do not invent an elaborate tactical
scene when the fiction has no spatial basis; emit `present=false` with empty
lists instead. The seed is tactical context, not an observable fact.

For `dnd_combat_end`, set `requires_responders=false`,
`required_responders=[]`, and `combatant_ids=[]`.

For every mode except `dnd_combat_start`, set `combatant_spawns=[]`.

### D&D Observer Routing Extension

In D&D mode, `observers[].routing_role` also allows `dnd_reaction`.
Use `dnd_reaction` only for a direct observer in active combat who should
receive a player-facing reaction prompt before combat advances. This is a
ruleset-specific routing role, not a generic narrative response. Use
`observe_only` for combatants who merely see the event, and leave ordinary
NPC follow-up pressure as `next_output` only outside initiative-locked combat.

### D&D Loot Offers

`loot_offer` represents visible items or coins a player character may choose to
add to inventory after the event. It is a choice surface, not a resolved
inventory mutation.

Set `loot_offer.present=true` only when the current event makes takeable
contents visible or explicitly offered: searching a body, opening a container,
receiving a quest reward, accepting an unopposed handoff, or completing a clear
reward transfer. Do not use it for hidden contents, possible traps, curses,
unidentified magical properties, or ordinary shop stock that still requires an
unresolved purchase.

When the offer is private to one character, set `visibility="private"` and put
only that character in `eligible_character_ids`. When the table can see and
reasonably claim it, set `visibility="table"` and list the player character ids
who can choose from it. If the item is not identified, use its visible surface
name, set `identified=false`, and put unknown details in `notes` only if the
character can perceive them.

When no loot is available, emit the full `loot_offer` object with
`present=false`, `source_kind="other"`, empty strings/lists, and zero currency.
