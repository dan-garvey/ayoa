<instructions>
Use recent facts, compact router knowledge state, candidate characters, and the reviewed router knowledge dispatch index to decide what imported-content knowledge changed and what the router needs now.

Only choose keys that appear in the dispatch index. Do not invent keys, refs, characters, facts, outcomes, actions, turn order, or narration. Do not quote source material, request images, include paths, or include raw extracted text.

Dispatch keys are not content refs. A value shown as `key=...` may be used only in `router_required_keys` or `router_turn_candidates.related_keys`; it must never appear in any `ref` field. Ref-bearing arrays require exact reviewed content refs that are already visible as `pack:ref` tokens in router knowledge state or another ref-bearing input. If you cannot see an exact ref token, leave `knowledge_updates` and `agent_context_broadcasts` empty and use dispatch keys instead.

Return `knowledge_updates` only as patch operations for one specific entity. `entity_id` is required and must exactly match an entity from candidate characters or current router knowledge state; never use a blank, group, scene, party, global, or inferred entity id. Use `operation="mark_known"` for established knowledge, `operation="mark_suspected"` for plausible but uncertain knowledge, and `operation="forget"` only when recent facts clearly invalidate a prior knowledge entry. If reviewed content is needed by the router but is not newly known by one specific entity, put its dispatch key in `router_required_keys`, not `knowledge_updates`.

Return `router_required_keys` when the router needs reviewed content for the next decision. Each item must contain only `key` and a concise debug-only `reason`. Keys are deltas, not the whole map, and should not repeat keys already marked known in router knowledge state.

Return `router_turn_candidates` only for candidate characters who may plausibly want router attention because the recent facts touch their pressure, goals, location, resources, responsibilities, or knowledge channels. A candidate is not permission to act and does not decide whether the character gets a turn.

Return `agent_context_broadcasts` only for rare character-agent context changes that should reach a character even if the router does not need the ref. Use this sparingly and only for candidate characters.

For each ref-bearing `knowledge_updates` or `agent_context_broadcasts` item, fill `pack_id`, `ref`, `content_hash`, `reason`, and `source_fact_ids`. Use `content_hash=""` unless a hash is shown.

For each router turn candidate, fill `character_id`, `priority`, `reason`, `source_fact_ids`, and `related_keys`. Use related keys from the dispatch index.

Keep reasons concise: one short clause or sentence. Do not restate the full recent-fact history, current knowledge map, or catalog.

Return empty arrays and a concise `no_update_reason` when recent facts do not require knowledge changes, router content, agent context, or character attention.
</instructions>
